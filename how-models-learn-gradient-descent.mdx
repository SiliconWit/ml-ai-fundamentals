So far, `np.polyfit` and scikit-learn found the best numbers of a model for you. When a fit fails, when the error stops falling, or when training takes hours, you cannot repair a method you have never looked inside. Gradient descent is the method that finds the adjustable numbers of most models, from logistic regression to neural networks. The idea fits in one sentence: measure how wrong the model is, find the direction in which each number should change, take a small step, and repeat. In this lesson you write it yourself in a few lines of NumPy, so that you can watch every number change at every step and recognize the common failures. #GradientDescent #Optimization #MachineLearning

## The blindfolded hill analogy

You stand on a hillside with your eyes covered and want to reach the lowest point of the valley. You feel the slope under your feet, step the way that goes down, feel again, and step again. After many small steps you are at the bottom, or close to it.

That is gradient descent:

- The height of the ground is the **loss**: one number that says how wrong the model is. The **loss function** gives it for every setting of the adjustable numbers, which are called **parameters** or weights.
- The slope you feel is the **gradient**. It points in the direction in which the loss rises fastest, so you step the opposite way.
- The length of your step is set by the **learning rate**.

A hillside has two directions. A model has one direction for each parameter, often thousands, and the rule is the same in every one.

```text
  loss
    │ ●  start
    │  \
    │   \     the gradient points uphill,
    │    \    so each step goes the other way
    │     \
    │      \
    │       \
    │        \______●  lowest loss
    └────────────────────────────────►
          value of one parameter, w
```

Each step applies one rule: the new value of a parameter is its old value minus the learning rate times the gradient.

$$
w_{\text{new}} = w_{\text{old}} - \eta \times \text{gradient}
$$

Here $w$ is a parameter and $\eta$ (the Greek letter eta) is the learning rate, written `lr` in the programs. The whole method is a loop:

```mermaid
flowchart TD
    A[Initialize weights randomly] --> B[Forward pass:\ncompute predictions]
    B --> C[Compute loss:\nhow wrong is the model?]
    C --> D{Loss small enough?}
    D -- No --> E[Compute gradient:\ndirection of steepest increase]
    E --> F[Update weights:\nw = w - lr * gradient]
    F --> B
    D -- Yes --> G[Training complete]
```

## The loss function: how wrong is the model?

<InArticleAd />


Before you can improve a model, you need one number that says how wrong it is. For regression the usual loss function is the **mean squared error** (MSE): the average of the squared differences between the actual values and the predictions.

$$
\text{MSE} = \frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2
$$

Here $n$ is the number of examples, $y_i$ is the actual value of example $i$, and $\hat{y}_i$ is the prediction for it. The symbol $\sum$ means "add this up for all the examples".

Squaring does two things. It makes every error positive, and it makes large errors count more than small ones. A prediction that is wrong by 10 adds 100 to the sum, and a prediction that is wrong by 1 adds only 1.

## The gradient: which way is downhill?

<InArticleAd />


The gradient of the loss for one parameter says how the loss changes when that parameter rises a little. If the gradient is positive, a higher value gives a higher loss, so you lower the parameter. If it is negative, you raise it.

Take a line with one feature, $\hat{y} = wx + b$, with slope $w$ and intercept $b$. The symbol $\partial \text{MSE} / \partial w$ is read "the change in the MSE for a small change in $w$, with $b$ held still". The two gradients are:

$$
\frac{\partial \text{MSE}}{\partial w} = \frac{-2}{n} \sum_{i=1}^{n} x_i (y_i - \hat{y}_i)
$$

$$
\frac{\partial \text{MSE}}{\partial b} = \frac{-2}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)
$$

Both come from the MSE formula by the rules of calculus, and for larger models software derives them. Each one is an average of the errors $(y_i - \hat{y}_i)$. When the predictions are too low on average, both gradients are negative, and the update rule raises $w$ and $b$.

## Gradient descent in 25 lines

<InArticleAd />


Here is linear regression fitted by gradient descent alone, with NumPy and no scikit-learn. The data follows $y = 3x + 7$ with noise. One pass of the loop, which uses all the data once, is called an **epoch**.

```python
import numpy as np

np.random.seed(42)

# ── Generate data: y = 3x + 7 + noise ──
n = 100
x = np.random.uniform(0, 10, n)
y = 3 * x + 7 + np.random.randn(n) * 2

# ── Initialize parameters randomly ──
w = np.random.randn()  # weight (slope)
b = np.random.randn()  # bias (intercept)
lr = 0.01              # learning rate
epochs = 2000          # number of iterations

print(f"True parameters:    w = 3.000, b = 7.000")
print(f"Initial parameters: w = {w:.3f}, b = {b:.3f}")
print()

# ── Gradient descent loop ──
losses = []
for epoch in range(epochs):
    # Forward pass: compute predictions
    y_pred = w * x + b

    # Compute loss (MSE)
    loss = np.mean((y - y_pred) ** 2)
    losses.append(loss)

    # Compute gradients
    dw = -2 * np.mean(x * (y - y_pred))  # gradient w.r.t. weight
    db = -2 * np.mean(y - y_pred)         # gradient w.r.t. bias

    # Update parameters (step downhill)
    w = w - lr * dw
    b = b - lr * db

    # Print progress every 200 epochs
    if epoch % 200 == 0 or epoch == epochs - 1:
        print(f"Epoch {epoch:>4d}: loss = {loss:.4f}, w = {w:.4f}, b = {b:.4f}")

print(f"\nFinal parameters: w = {w:.3f}, b = {b:.3f}")
print(f"True parameters:  w = 3.000, b = 7.000")
print(f"Final loss: {losses[-1]:.4f}")
```

The loop ends at about $w = 2.908$ and $b = 7.430$ with a loss of about 3.23: the least-squares line for these 100 noisy points, close to the true 3 and 7 but not equal. $w$ is almost right after 200 epochs, and $b$ needs more than 1,000. The feature $x$ runs from 0 to 10 and is not scaled, so the loss is a long narrow valley: steep in the $w$ direction and nearly flat in the $b$ direction.

That is the complete algorithm, and larger models run the same loop with more parameters.

## Learning rate: the most important hyperparameter

<InArticleAd />


The learning rate sets the length of each step. It is a **hyperparameter**: a setting that you choose, not a number that the model learns. The program runs the same fit with four learning rates.

## Connection to PID control

<InArticleAd />


Gradient descent is a feedback loop. A controller measures an error, corrects in proportion to it, and repeats; gradient descent corrects each parameter in proportion to its gradient, and repeats.

| Control loop | Gradient descent |
|---|---|
| Error signal | Gradient of the loss |
| Controller gain | Learning rate |
| Controller output | Change made to the parameters |
| Response of the plant | New predictions and a new loss |

The learning rate behaves as the gain does. Too low, and the loop is slow. Too high, and it overshoots, oscillates and at last runs away.

<Card title="Connect to Applied Math" icon="star">
For a straight-line model the best parameters can be calculated directly, by setting the derivative of the loss to zero and solving the equations that result (the normal equations). This is what `np.polyfit` does. Gradient descent is for the models where those equations cannot be solved directly, such as logistic regression and neural networks.
</Card>

## Multivariate gradient descent

<InArticleAd />


The same method works with several features: one weight for each feature, and one gradient for each weight. The program below has three features. It scales them first, so that the loss is a round bowl, equally steep in every direction, and one learning rate fits all the weights.

```python
import numpy as np
import matplotlib.pyplot as plt

np.random.seed(42)

# ── Generate multi-feature data ──
# True relationship: y = 2*x1 + (-1)*x2 + 0.5*x3 + 5 + noise
n = 200
X = np.random.randn(n, 3)
w_true = np.array([2.0, -1.0, 0.5])
b_true = 5.0
y = X @ w_true + b_true + np.random.randn(n) * 0.5

# ── Feature scaling (important for gradient descent) ──
X_mean = X.mean(axis=0)
X_std = X.std(axis=0)
X_scaled = (X - X_mean) / X_std

# ── Gradient descent ──
w = np.random.randn(3)
b = 0.0
lr = 0.05
epochs = 300

losses = []

print(f"True parameters:    w = {w_true}, b = {b_true:.1f}")
print(f"Initial parameters: w = [{w[0]:.3f}, {w[1]:.3f}, {w[2]:.3f}], b = {b:.3f}")
print()

for epoch in range(epochs):
    # Forward pass
    y_pred = X_scaled @ w + b

    # Loss
    loss = np.mean((y - y_pred) ** 2)
    losses.append(loss)

    # Gradients (vectorized)
    error = y - y_pred
    dw = -2 / n * (X_scaled.T @ error)   # shape: (3,)
    db = -2 / n * np.sum(error)           # scalar

    # Update
    w = w - lr * dw
    b = b - lr * db

    if epoch % 50 == 0 or epoch == epochs - 1:
        print(f"Epoch {epoch:>4d}: loss = {loss:.4f}, w = [{w[0]:.3f}, {w[1]:.3f}, {w[2]:.3f}], b = {b:.3f}")

# ── Unscale weights to compare with true values ──
w_unscaled = w / X_std
b_unscaled = b - np.sum(w * X_mean / X_std)

print(f"\nFinal (unscaled): w = [{w_unscaled[0]:.3f}, {w_unscaled[1]:.3f}, {w_unscaled[2]:.3f}], b = {b_unscaled:.3f}")
print(f"True:             w = [{w_true[0]:.3f}, {w_true[1]:.3f}, {w_true[2]:.3f}], b = {b_true:.3f}")

# ── Plot loss curve ──
plt.figure(figsize=(8, 5))
plt.plot(losses, color='steelblue', linewidth=2)
plt.xlabel('Epoch')
plt.ylabel('MSE Loss')
plt.title('Multivariate Gradient Descent: Loss Curve')
plt.grid(True, alpha=0.3)
plt.yscale('log')
plt.tight_layout()
plt.savefig('multivariate_gd_loss.png', dpi=100)
plt.show()
print("\nPlot saved as multivariate_gd_loss.png")
```

With scaled features the loss reaches its lowest value, 0.25, within about 100 epochs, at a learning rate five times larger than before.

## Batch vs stochastic gradient descent

<InArticleAd />


So far every step used all the training samples to calculate the gradient. This is **batch gradient descent**. With a million samples each step is slow, so there are two other ways:

| Method | Samples used for each step | Behaviour |
|---|---|---|
| Batch | All of them | Smooth and steady, but each step is slow on a large data set |
| Stochastic (SGD) | One, chosen at random | Each step is very fast, but the path is noisy and zig-zags |
| Mini-batch | A random group, often 32 or 64 | Faster than batch and smoother than SGD |

Mini-batch is the usual choice, and it is how neural networks are trained.

```python
import numpy as np
import matplotlib.pyplot as plt

np.random.seed(42)

# ── Generate data ──
n = 200
x = np.random.uniform(0, 10, n)
y = 3 * x + 7 + np.random.randn(n) * 2

# ── Batch Gradient Descent ──
def run_gd(x, y, mode='batch', batch_size=32, lr=0.01, epochs=100):
    """Run gradient descent in batch, stochastic, or mini-batch mode."""
    np.random.seed(42)
    w, b = np.random.randn(), np.random.randn()
    losses = []

    for epoch in range(epochs):
        # Full loss for tracking (always computed on all data)
        y_pred_full = w * x + b
        losses.append(np.mean((y - y_pred_full) ** 2))

        if mode == 'batch':
            # Use all data
            x_batch, y_batch = x, y
        elif mode == 'sgd':
            # Use one random sample
            idx = np.random.randint(0, len(x))
            x_batch, y_batch = x[idx:idx+1], y[idx:idx+1]
        elif mode == 'mini-batch':
            # Use a random subset
            idx = np.random.choice(len(x), batch_size, replace=False)
            x_batch, y_batch = x[idx], y[idx]

        y_pred = w * x_batch + b
        dw = -2 * np.mean(x_batch * (y_batch - y_pred))
        db = -2 * np.mean(y_batch - y_pred)
        w -= lr * dw
        b -= lr * db

    return losses, w, b

# ── Run all three modes ──
# Here one "epoch" is one parameter update (one step), so that the
# three modes are compared step for step.
epochs = 2000
losses_batch, w_b, b_b = run_gd(x, y, mode='batch', lr=0.01, epochs=epochs)
losses_sgd, w_s, b_s = run_gd(x, y, mode='sgd', lr=0.01, epochs=epochs)
losses_mini, w_m, b_m = run_gd(x, y, mode='mini-batch', batch_size=32, lr=0.01, epochs=epochs)

print(f"{'Mode':<15} {'Final Loss':<12} {'w':<10} {'b':<10}")
print("-" * 47)
print(f"{'Batch':<15} {losses_batch[-1]:<12.4f} {w_b:<10.4f} {b_b:<10.4f}")
print(f"{'SGD':<15} {losses_sgd[-1]:<12.4f} {w_s:<10.4f} {b_s:<10.4f}")
print(f"{'Mini-batch':<15} {losses_mini[-1]:<12.4f} {w_m:<10.4f} {b_m:<10.4f}")
print(f"{'True':<15} {'':12s} {'3.0000':<10} {'7.0000':<10}")

# ── Plot ──
fig, axes = plt.subplots(1, 3, figsize=(16, 5))

modes = [('Batch', losses_batch, 'steelblue'),
         ('SGD', losses_sgd, 'tomato'),
         ('Mini-batch (32)', losses_mini, 'seagreen')]

for ax, (name, losses, color) in zip(axes, modes):
    ax.plot(losses, color=color, linewidth=1.5, alpha=0.8)
    ax.set_xlabel('Epoch')
    ax.set_ylabel('MSE Loss')
    ax.set_title(f'{name}: Final loss = {losses[-1]:.4f}')
    ax.grid(True, alpha=0.3)
    ax.set_yscale('log')

plt.suptitle('Batch vs SGD vs Mini-Batch Gradient Descent', fontsize=13)
plt.tight_layout()
plt.savefig('gd_modes_comparison.png', dpi=100)
plt.show()

print("\nNotice:")
print("  Batch: smooth, steady descent.")
print("  SGD: noisy, zig-zag path (each step uses one sample).")
print("  Mini-batch: moderate noise, good balance.")
print("\nPlot saved as gd_modes_comparison.png")
```

After 2,000 steps the three are close to each other: batch gives $w = 2.98$ and $b = 7.21$, SGD gives 2.83 and 7.62, and mini-batch gives 2.95 and 7.17. The loss of SGD jumps up and down on the way, because each step looks at one sample only.

## Beyond vanilla gradient descent

<InArticleAd />


The plain rule `w -= lr * gradient` is called **vanilla** gradient descent. Libraries offer variants that improve it in two ways. **Momentum** keeps part of the previous step, so steps in a steady direction add up and zig-zags cancel. An **adaptive learning rate** gives every parameter its own step size.

```text
  Vanilla:         w -= lr * g
  Momentum:        v = beta*v + g;   w -= lr * v
  Adam (default):  tracks running mean AND variance of g,
                   adjusts step size for every parameter
```

Adam combines both and is the usual first choice in PyTorch (`torch.optim.Adam`) and in TensorFlow. It usually needs fewer steps and is less sensitive to the learning rate. Every variant still calculates the same gradient and still steps downhill.

A **learning rate schedule** is another common tool: start with larger steps and make them smaller as training goes on.

<Card title="Why linear regression always arrives and a neural network may not" icon="star">
The loss of linear regression (and of logistic regression) is **convex**: one bowl with one lowest point. Gradient descent reaches it from any start, if the learning rate is small enough.

The loss of a neural network is **not convex**. It has many low points, and gradient descent stops in the one it reaches first, which need not be the lowest. In practice many of them give models that work about equally well.
</Card>

## The complete gradient descent lab

<InArticleAd />


This last program joins the parts: gradient descent written by hand, plots of its progress, and a comparison with the exact answer that scikit-learn calculates directly.

```python
import numpy as np
import matplotlib.pyplot as plt
from sklearn.linear_model import LinearRegression

np.random.seed(42)

# ── Generate data ──
n = 150
x = np.random.uniform(0, 10, n)
y = 3 * x + 7 + np.random.randn(n) * 2

# ── Gradient Descent Implementation ──
def gradient_descent(x, y, lr=0.01, epochs=500):
    w, b = 0.0, 0.0
    losses, ws, bs = [], [], []

    for epoch in range(epochs):
        y_pred = w * x + b
        loss = np.mean((y - y_pred) ** 2)
        losses.append(loss)
        ws.append(w)
        bs.append(b)

        dw = -2 * np.mean(x * (y - y_pred))
        db = -2 * np.mean(y - y_pred)
        w -= lr * dw
        b -= lr * db

    return w, b, losses, ws, bs
```

## Key takeaways

<InArticleAd />


<Steps>
1. **Gradient descent is one loop.** Predict, compute the loss, compute the gradient, update the parameters.

2. **The loss function measures how wrong the model is.** MSE for regression, cross-entropy for classification.

3. **The gradient points uphill, and you step downhill.** The update rule is `parameters -= learning_rate * gradient`.

4. **The learning rate decides whether training works.** Too large, and the loss grows without end. Too small, and training takes far too long. Start with 0.01 and adjust.

5. **Scale the features.** Features on different scales make the loss steep in one direction and flat in another, and no single learning rate fits both.

6. **Gradient descent and the exact solution agree.** Gradient descent is for the models that have no exact solution.

7. **Mini-batch is the practical choice.** It is faster than batch and steadier than SGD.
</Steps>
